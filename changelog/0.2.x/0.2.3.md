# 0.2.3 — 2026-07-26

## Added

- **`ris_search_case_law` `norm_index`** — optional object (`title`, `abbreviation`, `type`, `reference`) naming the law a `court: normenliste` record indexes; absent on the sixteen deciding courts. `abbreviation` prefers `AbkuerzungDesVerwaltungsgerichtshofes` over `Abkuerzung` — the citable form (`DSG 2000`, `HlG 1989`) rather than the often-repeated full title. ([#19](https://github.com/cyanheads/ris-austria-mcp-server/issues/19))
- **`ris_search_case_law` `indexes` / `state` / `note`** — flat fields on `CaseLawRecordSchema`: Systematik classification entries (vfgh, vwgh, lvwg, uvs, umse, normenliste), the deciding Bundesland (lvwg, uvs), and an Anmerkung (normenliste, justiz, dsk). ([#22](https://github.com/cyanheads/ris-austria-mcp-server/issues/22))
- **`ris_search_legislation` `translation`** — optional object (`source`, `author`) giving English-translation provenance on `Erv` records, which otherwise carry no `in_force_from`, `promulgation`, or `eli` to say which German version they correspond to. ([#22](https://github.com/cyanheads/ris-austria-mcp-server/issues/22))

## Fixed

- **`stripHtmlRemnants`** — normalizes CRLF line endings before stripping `<br/>` markers. Normenliste `Titel`/`Fundstelle` are CRLF-delimited upstream and previously reached callers as escape noise. ([#19](https://github.com/cyanheads/ris-austria-mcp-server/issues/19))
- **`mapBundesrecht`** — `Erv.Author`/`Erv.Source` now run through the same HTML-stripping path as every other text field; both are `<br/>`-separated prose upstream (18 of 100 sampled `Author` values name an amending body). ([#22](https://github.com/cyanheads/ris-austria-mcp-server/issues/22))
- **`RisService` search retry budget** — `SEARCH_TIMEOUT_MS` 15s → 40s: a filtered search answers in 0.6–3s, but an unfiltered `bvwg` page costs 14.6–43s at `page_size` 50–100, which the old deadline could never complete. A new `SEARCH_BUDGET_MS` (48s) caps the whole retry sequence — each attempt gets whatever budget remains — so a slow-failing upstream can't multiply the deadline by the attempt count. A search deadline (`errorSource: 'FetchTimeout'`) is no longer retried, since a request that can't finish in 40s is an expensive scan, not a blip; an upstream 504 stays retryable. Worst case is now ≈55s, inside the MCP SDK's 60s default request timeout (previously ≈73s). `trackChanges()` shares the new budget via one `request()` helper. ([#23](https://github.com/cyanheads/ris-austria-mcp-server/issues/23))
