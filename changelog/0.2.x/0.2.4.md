# 0.2.4 — 2026-07-26

## Fixed

- **`isoDateString`** — validates a real calendar date, not just the `YYYY-MM-DD` shape. The tightened pattern (`^\d{4}-(?:0[1-9]|1[0-2])-(?:0[1-9]|[12]\d|3[01])$`) reaches the advertised JSON Schema, so a schema-validating client rejects an impossible date like `2026-99-99` without a round trip; a `.refine()` catches the shape-valid impossibilities the pattern can't express (31 April, 29 February outside a leap year). Backs all 20 date parameters across 7 tools. `ris_lookup_citation` previously converted RIS's upstream rejection of an impossible date into `found: false`, misreporting bad input as an unresolved citation. ([#14](https://github.com/cyanheads/ris-austria-mcp-server/issues/14))
- **`ris_lookup_citation` `court`** — the enum drops `normenliste` (a norm index that carries no case numbers); the request builder rejected a Geschäftszahl filter there, and `runSearch()` turned that local rejection into the same `found: false` miss as an unresolved citation. ([#14](https://github.com/cyanheads/ris-austria-mcp-server/issues/14))
- **`normGuidance()`** — takes the full parsed citation instead of a loose abbreviation/section pair, so an Artikel miss labels the section `Art N` (not `§ N`) and carries `section_type: 'Artikel'` into the `ris_search_legislation` retry recipe. The prior recipe omitted it, defaulted to `Paragraph`, and returned zero hits for an Artikel that exists. ([#17](https://github.com/cyanheads/ris-austria-mcp-server/issues/17))
- **`RIS_COURTS` `gzExample`** — vwgh (`Ra 2019/22/0184` → `Ro 2026/03/0016`) and justiz (`6Ob56/25k` → `14Os49/26a`) replaced with citations confirmed against the live RIS corpus; the originals resolved zero hits. Updated across all six prose copies: the `ris_lookup_citation` tool and `citation` field descriptions, `unknownGuidance()`, the `ris_search_case_law` zero-hit notice, `RIS_CITATION_FORMATS`, and the README feature bullet. ([#18](https://github.com/cyanheads/ris-austria-mcp-server/issues/18))
- **`docs/design.md`** — the errors table now documents `upstream_timeout` (Timeout, retryable) alongside `upstream_error`; `ris_lookup_citation` has declared the distinct reason since before this release, but the doc still described only one.
