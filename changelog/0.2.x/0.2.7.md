# 0.2.7 — 2026-07-31

## Fixed

- **Local rejections name the caller's own input** — `ris_search_case_law`, `ris_search_gazette`, and `ris_search_announcements` rewrite request-builder rejections at their existing `.catch()` into the tool's own vocabulary before they reach the wire. A rejection previously read the builder's internal service param name and RIS application code (e.g. `sortBy`, `Normenliste`) instead of the field and value the caller actually sent (`sort_by`, `court: 'normenliste'`). `unsupported()` in `request-builder.ts` now carries the rejection as separate `param`, `value`, and `alternatives` data instead of one fused `sortBy: <value>` identifier; `rewriteUnsupportedParam` (new, `_shared.ts`) reads that data and swaps in each tool's own message, or leaves the builder's message untouched when the tool has nothing more precise to say. ([#29](https://github.com/cyanheads/ris-austria-mcp-server/issues/29))
- **Gazette rejections name the routing input** — `resolveFederalTier` now returns `routedBy` (the `number`, `part`, or date bound that selected a federal era tier), and `gazetteLabel` (new) names the resolved gazette by that selection so `type`/`part`/`issuer`/`number`/`sort_by` rejections state which tier or scope rejected the field, rather than an internal application code. Each corrective was checked against the live API to hold for every call it answers.
- **Out-of-range `page` recovery** — all five search tools (`ris_search_legislation`, `ris_search_case_law`, `ris_search_gazette`, `ris_search_drafts`, `ris_search_announcements`) lead their `invalid_query` recovery hint with "For a page past the end, request a lower page, starting from 1" ahead of the existing per-tool guidance, and their `when` clause now names the out-of-range page as a cause. ([#30](https://github.com/cyanheads/ris-austria-mcp-server/issues/30))

## Changed

- `docs/design.md`'s `invalid_query` rows for all five search tools reconciled with the shipped `when`/`recovery` text.
