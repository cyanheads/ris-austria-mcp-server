# 0.1.7 — 2026-07-15

## Fixed

- **RIS's HTTP 500 for a rejected input parameter** (e.g. `ris_track_changes` with a `page` past the last page) now classifies through the same envelope translator as the existing 200-status in-band error path — `InvalidParams` with RIS's own message, instead of an opaque `InternalError`. Fixed once in `RisService.fetchJson` / `normalizer.ts`, so all six search-shaped tools inherit it through their existing `.catch()` blocks with no tool-file changes needed. ([#9](https://github.com/cyanheads/ris-austria-mcp-server/issues/9))
- Some RIS fault messages hide the `soap:Client`/`soap:Server` classification prefix behind .NET exception scaffolding — most visibly Landesrecht, which wraps the whole fault a second time (`Bka.Ris.…OgdException: soap:Client…`), previously misclassifying a deterministic input rejection as transient `ServiceUnavailable` and retrying it. The scaffolding is now stripped before classification.

## Changed

- **`ris_track_changes`'s `invalid_query` contract** — `when` now cites an out-of-range `page` (the reachable cause) instead of an unknown application name (unreachable — rejected locally by the input's Zod enum before any request reaches RIS); `recovery` leads with the page instead of pointing at `ris_list_reference topic applications`. ([#10](https://github.com/cyanheads/ris-austria-mcp-server/issues/10))
- **Tool descriptions** — `ris_get_document`'s `sections` param now says "markdown only" instead of "text formats" (raw `html`/`xml` never route through the outline logic and always return in full); its `enrichment.notice` description drops "Agent-facing" for reader-neutral phrasing. "expanded server-side" → "expanded" throughout `ris_search_drafts` and `ris_search_announcements`; `ris_track_changes`'s description drops "History controller" / "handled internally" mechanism language. ([#8](https://github.com/cyanheads/ris-austria-mcp-server/issues/8))
- **Dependencies** — `@types/node` 26.1.0 → 26.1.1, `ignore` ^7.0.5 → ^7.0.6; `devcheck.config.json`'s outdated-allowlist adds `typescript` alongside the existing `@cyanheads/mcp-ts-core` entry.
