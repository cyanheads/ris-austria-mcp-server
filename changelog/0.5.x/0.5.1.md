# 0.5.1 — 2026-10-08

## Changed

- **Tool and resource error `data` carries `requestId`**, and a tool error's text closes with `request <id>` (mcp-ts-core 0.13.10).
- **Error `data` no longer carries stack traces** (0.13.7), request context (0.13.8), or `rootCause` (0.13.13); fetch errors name a URL by origin only (0.13.12).
- **Tool-argument pre-validation repairs more inputs instead of rejecting them**: an integer sent for a string and a JSON-stringified object (0.13.9); numeric or boolean strings, a lone string for an array, and `null` at an optional key (0.13.14).
- **`ctx.fail` throw sites name only the reason**; the framework fills the declared `recovery` from the `errors[]` entry (0.13.10). Tests assert the hint on the contract path (`runToolContract`, the worker handler).
- **`server.json` npm entries set `runtimeHint: "npx"`** and drop the `run start:*` arguments; the `streamable-http` entry fixes `MCP_TRANSPORT_TYPE` as `http` (0.13.11).
- **Docker**: a `deps` stage on `$BUILDPLATFORM` cross-installs production dependencies with `--os`/`--cpu` and installs the OTel peers at the framework's declared ranges with `scripts/install-otel.ts` (0.13.10), then drops musl-only bindings with `scripts/prune-musl-packages.ts` (0.13.11), so a multi-arch build no longer runs Bun under QEMU; the image's installs pass `bunfig.toml`'s release-age gate and security scanner (0.13.8); base images `oven/bun` 1.4.0 → 1.4.2 (0.13.7); `ENV MCP_FORCE_CONSOLE_LOGGING` removed (0.13.8).
- **`.dockerignore` excludes every `.env*` file** and the MCP Registry token files, and `.gitignore` ignores `.env*` except `.env.example`, `.env.template`, and `.env.sample` (0.13.11); `.mcpbignore` excludes `docs/idea.md` and `logs/` (0.13.9).
- **`package.json`** adds `"!dist/*.mcpb"` to `files` (0.13.8) and sets `packageManager` `bun@1.4.2` (0.13.7).
- **`.env.example`** documents the per-signal `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` / `_METRICS_ENDPOINT` (0.13.7), `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` (0.13.8), `MCP_REQUEST_STATE_KEY` (0.13.10), and `LOG_LLM_INTERACTIONS` (0.13.13).
- **`.github/workflows/codeql.yml`** runs a per-language matrix (`actions`, `javascript-typescript`), each uploading under `/language:<language>` (0.13.11).
- **Framework scripts resynced** (`devcheck`, `lint-mcp`, `lint-packaging`, `release-github`, `check-skill-versions`, `check-framework-antipatterns`): `lint:packaging` checks `"!dist/*.mcpb"` in `files` (0.13.8), the manifest version and the Dockerfile build platform (0.13.9, 0.13.10), and the `server.json` npm launch shape (0.13.11); `lint:mcp` fails on a definition or `server.json` it cannot load, and `release:github` validates the tag annotation (0.13.9); devcheck's TODO scan works on macOS and its secret-file scan covers root-level files (0.13.11); the antipattern gate's whitespace match works on macOS (0.13.13).
- **`framework-skills/`** synced to mcp-ts-core 0.13.14; `CLAUDE.md`, `AGENTS.md`, and the README badges updated to the new framework, MCP SDK, and Bun versions.

## Fixed

- **`ris-service` debug log** `RIS content fetched` records the rendition file name (`file`) instead of the full URL, keeping URLs out of log fields as mcp-ts-core 0.13.12 does for its own records.
