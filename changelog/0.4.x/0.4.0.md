# 0.4.0 — 2026-07-31

## Changed

- **`ris_search_drafts` `materials[].url`** — `materials[].urls` (an object of up to four rendition URLs) collapses to a single `materials[].url`: the companion's HTML rendition, or its PDF where RIS files no HTML one (roughly one companion in eight, nearly all Begut covering letters). `ris_get_document` validates a companion URL's extension and then discards it, rebuilding the rendition from its own `format` input, so one URL already reached every rendition the companion has — the four-URL set was duplication. Cuts `structuredContent` 38–46% across sampled page sizes. **Breaking** for anything reading `materials[].urls.html` (or `.xml`/`.pdf`/`.rtf`). ([#34](https://github.com/cyanheads/ris-austria-mcp-server/issues/34))
- **`document_url` refusal messages** — split into their three distinct causes (unrenderable extension, path nested below the document folder, unrecognized filename) instead of one message that told a caller who had copied a URL verbatim to copy a URL verbatim.

## Fixed

- **`ris_get_document` companion filename acceptance** — `document_url` now accepts every companion filename shape RIS publishes, not only the `Materialien_`/`Schreiben_`/`Anlagen_` + UUID shape used on 2026 records. Adds the `COO_{n}_{n}_{n}_{n}` Fabasoft object address (79.7% of the live corpus, every companion filed before 2026) and the prefixless `{NNNN}_{UUID}` shape. Each is matched as a whole anchored alternative over hex digits, `_`, and its own literal prefix — never a prefix or substring test, which would also match the per-record inline formula images RIS names `Material-COO_…`/`Anlage-COO_…`. ([#35](https://github.com/cyanheads/ris-austria-mcp-server/issues/35))
- **Companion 404 recovery** — a companion document RIS publishes with no rendition in the requested format now gets a recovery hint pointing at `format: urls_only` and `content_urls.pdf`, instead of the generic `document_not_found` recovery written for `document_number` + `application` addressing.
