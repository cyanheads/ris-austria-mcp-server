# 0.4.3 — 2026-09-13

## Added

- **`RIS_API_BASE_URL` and `RIS_CONTENT_BASE_URL` are declared** in `server.json`, `manifest.json`, and both plugin manifests. Both were already read by `getServerConfig()`; a registry entry or one-click install now surfaces them, each falling back to the official RIS endpoint when left blank.
- **`bun run audit:fix`** runs `bun audit fix` — the first response to a transitive advisory, ahead of `bun update <name>` and `audit:refresh` (mcp-ts-core 0.13.0).

## Changed

- **Upstream error classification comes from the framework** — the local `reclassifyUpstreamServerError` shim is gone. An envelope-less 5xx on the search and content paths still reports `ServiceUnavailable`, since mcp-ts-core 0.12.4 stopped mapping any HTTP status to `InternalError`. The RIS in-band error envelope is still translated first, so a rejected parameter stays a `ValidationError`.
- **An HTTP 501 is not retried** — it carries `data.retryable: false` alongside the transient `ServiceUnavailable` code (mcp-ts-core 0.12.4), so a method RIS does not implement fails on the first attempt instead of spending the retry budget.
- **A caller disconnect reports `RequestCancelled` (-32011)** rather than `InternalError` (mcp-ts-core 0.12.4); `data.errorSource` stays `FetchAborted`.
- **A rejected tool argument returns the structured error envelope** — an unknown root key or failed constraint answers `isError: true` with `error.code` `-32602` (`InvalidParams`) in `structuredContent` and the same readable text in `content[]` (mcp-ts-core 0.12.7).
- **A blank or unsubstituted `${…}` value for a RIS variable reads as unset** (mcp-ts-core 0.13.0) — a one-click install that leaves an optional field empty now falls back to the documented default instead of failing URL validation.
- **Development skills moved from `skills/` to `framework-skills/`** (mcp-ts-core 0.13.0) — plugin hosts auto-load a root `skills/`, so installing this server no longer hands its development skills to the agent.
- **Bun engines floor raised to `>=1.4.0`** (mcp-ts-core 0.12.9). Node stays `>=24.0.0`, and the published container already runs Bun 1.4.
- **Inherited HTTP-transport fixes** — a trailing slash on `MCP_PUBLIC_URL` no longer doubles in advertised links and `MCP_RESPONSE_VERBOSITY` and `OAUTH_PROXY_*` are no longer recognized (mcp-ts-core 0.12.8, neither configured here); the landing page's curl snippet sends a handshake `initialize` accepts and a cancelled request's SSE stream closes immediately (0.12.9); records logged during `setup()` are replayed rather than dropped (0.12.5).
